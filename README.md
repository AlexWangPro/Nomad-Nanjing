# Nomad Nanjing v4.0

本版重点升级“发现与复访”：加入场景化办公地点推荐、我的办公清单、一键分享卡片，并保留 v3.9 的公开数据自动同步与最近 POI 推荐。

# Nomad Nanjing Railway v4.0

南京数字游民办公地图的 Railway 专用版本。


## v4.0 新增

- 首页新增“我今天去哪办公？”：按综合、深度工作、Zoom/通话、3 小时以上、尽量免费 5 种场景给出 3 个优先选择。
- 用户允许定位后，推荐算法会把当前位置距离纳入排序；不开定位仍可按地点质量、评分、安静度、Wi-Fi、插座等信息推荐。
- 顶部筛选改成更偏场景的入口：深度工作、Zoom/通话、坐 3h+、免费办公、地铁附近，再保留地点类型。
- “收藏”升级为“我的办公清单”：保留旧收藏，并可在本机新建多个自定义清单、添加/移除地点。无需注册登录。
- 地点详情新增“清单”和“分享卡片”。分享卡片为 1080×1350 PNG，手机支持系统分享时可直接发送到微信/小红书；否则自动保存图片。
- 分享链接支持 `?place=<地点ID>` 深链，别人打开后可直接进入对应地点详情。
- v3.9 的后台地点实时同步、最近 POI 推荐继续保留。

## 持久化数据库架构

- 不再使用 `data/db.json`
- 地点、投稿、审核记录、贡献者和系统设置存入 SQLite 数据库
- 压缩后的 WebP 照片也存入 SQLite 数据库，不再依赖 `data/uploads`
- 数据库文件固定保存在 Railway Volume：`/data/nomad-nanjing.sqlite`
- 每次数据变更自动保留最近 50 个状态版本
- Railway 生产环境未连接 Volume 时，应用拒绝启动，防止把数据写进临时容器
- 如果 Volume 中存在旧版 `db.json` 和 `uploads/`，首次启动会自动尝试迁移

## 为什么更新代码不会影响数据

Docker 镜像和 GitHub 仓库只包含程序代码。Railway Volume 挂载到 `/data` 后，数据库位于独立持久存储中：

```text
GitHub / Docker 镜像
└── 程序代码

Railway Volume /data
└── nomad-nanjing.sqlite
    ├── 地点
    ├── 用户投稿
    ├── 审核记录
    ├── 贡献者
    └── WebP 图片二进制
```

覆盖 GitHub 文件、删除仓库中的 `data` 文件夹或重新部署，都不会覆盖 Volume 中的数据库。

## 重要限制

当前 SQLite 架构适合本项目的早期和中低访问量阶段。Railway 服务保持 **1 个 Replica**，不要开启多副本并发写入。未来用户量明显增加时，可以迁移到 PostgreSQL。

## 已发布地点维护

- 管理员可以直接编辑已发布地点，保存后立即更新前台。
- 受邀贡献者可以编辑已发布地点，但修改默认进入管理员审核，不会直接覆盖公开数据。
- 地点编辑器可查看已有照片、单张删除、继续多选上传和重新上传，最终最多保留 8 张。
- 管理员批准贡献者修改后，公开信息和图片一次性更新；拒绝或待补充时，现有公开地点保持不变。
- 图片最终以 WebP 保存，常规手机照片控制在约 88–114KB，并优先保留 840–2200px 的有效尺寸。


## 手机图片处理

- 手机原图无需裁剪，浏览器会把原图逐张交给服务器处理。
- 服务器使用 Sharp 自动旋转、缩放并转换为 WebP，常规照片目标约 100KB（约 88–114KB）。
- 地点照片最多 8 张，点评照片最多 3 张；压缩完成后才进入最终表单，因此提交体积稳定。
- 服务器不可用时才启用浏览器本地压缩备用通道；不支持 WebP 编码的手机会先生成兼容 JPEG，最终仍由服务器保存为 WebP。
